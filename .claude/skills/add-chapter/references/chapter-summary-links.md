# Chapter summary links and preview checks

Read this before drafting or validating a chapter summary for a new chapter. The summary
format and Spanish prose conventions remain in [the main skill](../SKILL.md#3-chapter-summary--booknsummariesjs).

Summary entity links are generated by `mapa.js` using
`CharacterReference.buildMentionMatcher` / `findMentions`, not by the `<strong>` tags.
Inventory matching and rendered mention matching have different acceptance rules:
`match-entities.cjs` finding a name inside a label confirms only an inventory candidate,
not that the same short name will link in the summary. Compose first mentions from the
confirmed node's canonical label (subject to the parenthetical-label rules below).
For example, `Svik` finds id `svik`, but the summary must use `Svik Hrulfsson`
when no short-name alias is available. Do not add aliases or rename nodes merely to
make a drafted summary pass; use the existing supported name and verify its identity.
The chapter verifier checks that every `<strong>` term resolves completely to one node
using the shared matcher and the live archive's inventory and guides. Review that the resolved
node is the intended entity; the automated check cannot establish identity. Before emphasizing a term, check
it is not a name that [entity resolution, step 2](source-and-entity-workflow.md) already returned as `UNMATCHED` (by `match-entities.cjs`) or
`NO MATCHES` (by `search-descriptions.cjs`): a generic word that looks like a proper
noun — `Maður`, Old Norse for "man", is one observed case — has no node and will fail
the verifier with "does not resolve completely to one node"; render it as plain text
instead. Matching is case-sensitive: use canonical
capitalization (e.g. `Fell-Wolf`, `Tennur`, `Foso de los Vaesen`, `Runa Warding`) or a
supported alias. The matcher strips trailing parenthetical text from labels: for
`Alþing (Althing)`, emphasize `Alþing`; neither the parenthetical alias nor the full
parenthesized label resolves without a separate supported alias. A pronunciation suffix after the closing parenthesis
(e.g. `Oskutreð (Árbol de Ceniza) [pron. Oskutreth]`) prevents that stripping; for a
new node, keep the label as `Oskutreð (Árbol de Ceniza)` and put any needed
pronunciation in its description. Verify the short name before finalizing the summary.
When two distinct entities share a name, a parenthetical qualifier is stripped and cannot disambiguate their summary mentions (for example the Hundur-thrall versus the god). For a new entity, retain its canonical id and use a distinct non-parenthetical label such as `Hundur, Dios-Sabueso`; emphasize that complete label for the god and verify that each mention resolves to the intended id. Plain-text repetitions should resolve too.

When a story within a chapter borrows names from its audience, use roles such as
«el lobo» and «el hijo de la viuda» for fictional actions in the summary. Use
canonical names for people acting in the framing scene. The renderer scans plain
text as well as emphasized text, so a borrowed name can link to its namesake even
without `<strong>` markup.

A named era such as
`Friðaröld` needs its own non-structural node to be linkable; a mention only in the root
description does not suffice. The live summary dialog uses `chapter-list` and `chapter-pane` elements and the
shared renderer. Name resolution alone does not prove a link opens: the live
regression suite checks connection-viewer startup with empty guides and creature
links reaching nodes with relationships. Run `npm test` after the content settles.

## Source accuracy

Check the summary, events and relationships against the same source actions:

- Preserve action order and where the chapter ends. An intended voyage, capture or
  investigation is not a completed departure, interrogation or discovery.
- Resolve giver, recipient and object for handoffs; a nearby command or leadership
  role does not identify the recipient.
- For conversations continued across chapters, include only this chapter's contribution
  to the shared event. Separate spoken reports from the current POV's private inference,
  remembered dialogue and internal replies; retain the original uncertainty of retold reports.
- Keep unnamed speakers and attackers anonymous unless the source identifies them.
  A nearby name across a paragraph break does not settle attribution, in quiet dialogue
  or fast action. Distinguish an observed injury/result from an inferred actor or death.
- Preserve stated motives and each participant's knowledge. Collaborators, uninformed
  allies and victims can experience the same staged action differently. An observer's
  resemblance or guess does not confirm identity, lineage or a magical mechanism.
